## HTTP endpoints

All endpoints live in `api/v1/` and return `application/json` except `img.php`.
Every one of them starts by locating `bootstrap.php` (production path first, dev path as
fallback), so the same file works in both environments.

### `POST /v1/register.php`

Registers or updates a site. Called by the WordPress plugin when settings are saved.

**Authentication:** `X-Secret-Key` header must equal `config['shared_secret']`.
There is no per-site auth on this endpoint — the shared secret is the only gate.

**Request body** (`application/json`):

| Field             | Required | Notes                                                                            |
| ----------------- | -------- | -------------------------------------------------------------------------------- |
| `domain`          | yes      | Protocol and trailing slashes are stripped before storage                        |
| `team_id`         | yes      | Cast to int                                                                      |
| `api_token`       | yes      | 64-char hex, generated by the plugin                                             |
| `competition_ids` | no       | Defaults to `[config.league_ids.bundesliga]`                                     |
| `season`          | no       | Defaults to `config.default_season`                                              |
| `active_widgets`  | no       | Defaults to `config.default_widgets`                                             |
| `custom_labels`   | no       | Defaults to `[]`                                                                 |
| `notes`           | no       | Defaults to `''`                                                                 |
| `limit`           | —        | **Ignored.** `limit_last` / `limit_next` are taken from `api-config.php` instead |

**Side effects:** upserts the entry in `config/site-mapping.json`, then forces
`update_global_standings()` and `fetch_site_data()` so the site has data immediately.

**Responses:**

| Status | Body                                                                                          |
| ------ | --------------------------------------------------------------------------------------------- |
| 200    | `{success:true, message, domain, api_token, is_new, data:{fixtures_count, results_count}}`    |
| 200    | …or `{success:true, …, fetch_error}` when registration succeeded but the initial fetch failed |
| 400    | `{error:"Missing domain or team_id"}` / `{error:"Missing api_token…"}`                        |
| 403    | `{error:"Unauthorized"}` — secret mismatch                                                    |
| 405    | `{error:"Method Not Allowed"}`                                                                |

### `GET /v1/fetch.php`

Forces a refresh for one domain. Backs the plugin's **Refresh Data Now** button.

**Authentication:** `domain` + `token` query parameters; the token must match
`site-mapping.json → {domain}.api_token`.

**Parameters:**

| Param    | Required | Notes                             |
| -------- | -------- | --------------------------------- |
| `domain` | yes      | Must exist in `site-mapping.json` |
| `token`  | yes      | Per-domain token                  |

**Rate limit:** `intervals.http_rate_limit` minutes (default 5) between calls per domain,
tracked in `cron_state.sites.{domain}.last_manual_fetch`.

**Responses:**

| Status | Body                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------- |
| 200    | `{success:true, message:"Data refreshed successfully", data:{domain, fixtures_count, results_count, generated_at}}` |
| 400    | `{success:false, error:"Missing domain or token"}`                                                                  |
| 403    | `{success:false, error:"Invalid token"}` or `"Site is disabled"`                                                    |
| 404    | `{success:false, error:"Site not found"}`                                                                           |
| 405    | `{success:false, error:"Method Not Allowed. Use GET."}`                                                             |
| 429    | `{success:false, error:"Rate limit exceeded…", retry_after:<minutes>}`                                              |
| 500    | `{success:false, error:"Site mapping not found"}` or the fetch error                                                |

> **Debug logging:** this endpoint writes `backend/logs/fetch-debug.log` _before_ bootstrap
> runs, so a crash during bootstrap is still recorded. See
> [Known issues](architecture.md#known-issues--debt).

### `GET /v1/assets.php`

Enumerates every team and league logo a site needs — the input to the plugin's local-asset
download feature.

**Parameters:**

| Param    | Default                 | Notes                                                                              |
| -------- | ----------------------- | ---------------------------------------------------------------------------------- |
| `team`   | —                       | Mode 1 (recommended): scan this team's fixtures for all competitions and opponents |
| `league` | `78`                    | Also scans standings for the complete team list                                    |
| `season` | `config.default_season` |                                                                                    |

**Response:** `{success:true, data:{teams:[{id,name,logo}], leagues:[{id,name,logo}], meta:{team_id, league_id, season, teams_count, leagues_count}}}`,
or `{success:false, error}` with status 500.

> Currently dormant — the plugin's JS no longer resolves local assets. See
> [the plugin's integration doc](../../testwp/wp-content/plugins/buli-widgets/docs/backend-integration.md).

### `GET /v1/img.php`

Image proxy. Resizes, converts to WebP and caches.

**Parameters:**

| Param | Required | Notes                                                                                               |
| ----- | -------- | --------------------------------------------------------------------------------------------------- |
| `url` | yes      | Must match `^https://media\.api-sports\.io/` — this is an allowlist, not a general proxy            |
| `s`   | no       | Display size in px. Default `32`, clamped to `12…64`. The image is rendered at `min(s × 2, 150)` px |

**Behaviour:** cache hit → `readfile()` the stored WebP. Miss → fetch (5 s timeout, follows
redirects), multi-step downscale, `imagewebp(…, 100)`, write to
`api/cache/img/md5(url_s).webp`, then serve.

**Response headers:** `Content-Type: image/webp`,
`Cache-Control: public, max-age=2592000` (30 days), `X-Cache: HIT|MISS`.

**Errors:**

| Status | Body                                                           |
| ------ | -------------------------------------------------------------- |
| 400    | `Invalid URL` — missing or non-CDN URL                         |
| 502    | `Failed to fetch image` — upstream failure or body < 100 bytes |
| 502    | `Failed to decode image` — not a readable image                |

Size values used by the plugin: **12** (competition logos), **20** (team logos in match rows
and the standings table), **32** (form-widget header and opponent logos).

## JSON files

### `backend/config/site-mapping.json`

The registry of servable sites. Written by `register.php`, read by `fetch_site_data()`,
`fetch.php`, `fetch_all.php` and `cron/fetch_all.php`.

```json
[
  {
    "domain": "testwp.test",
    "team_id": 157,
    "competition_ids": [78],
    "season": 2025,
    "limit_last": 15,
    "limit_next": 15,
    "active_widgets": ["matches", "standings", "results"],
    "enabled": true,
    "api_token": "1e360d9c…cdee",
    "custom_labels": [],
    "notes": "",
    "created_at": "2025-11-25T20:52:17+00:00",
    "updated_at": "2026-03-14T16:12:21+01:00",
    "last_checked": "2026-03-14T16:12:21+01:00",
    "status": "active"
  }
]
```

- `enabled` — the cron skips anything falsy. `register.php` always sets it to `true`.
- `api_token` — **a secret.** Required by `fetch.php`; returned to the plugin that owns it.
- `season` — written at registration and kept for reference, but **no longer read**.
  `fetch_site_data()` always derives the season from the calendar, so `{domain}.json` and
  `standings.json` can never disagree.

> ⚠ Contains a credential per site. **Gitignored** — commit `site-mapping.example.json`
> instead, never this file.

### `backend/config/cron-state.json`

Runtime state. Read and written by the cron, `register.php` and `fetch.php`.

```json
{
  "global": {
    "api_standings_cache": [
      /* raw API standings rows, full fields */
    ],
    "api_cache_timestamp": "2026-05-12T11:24:20+02:00",
    "last_standings_update": "2026-05-12T11:24:20+02:00"
  },
  "sites": {
    "testwp.test": { "last_update": "2026-03-18T22:02:27+01:00" }
  }
}
```

| Key                                | Written by                  | Read by     | Purpose                                                                |
| ---------------------------------- | --------------------------- | ----------- | ---------------------------------------------------------------------- |
| `global.api_standings_cache`       | `update_global_standings()` | same        | Metadata (`form`, `status`, `update`) merged into the calculated table |
| `global.api_cache_timestamp`       | same                        | same        | Gates the next `getStandings()` call                                   |
| `global.last_standings_update`     | same                        | same        | Bookkeeping                                                            |
| `sites.{domain}.last_manual_fetch` | `fetch.php`                 | `fetch.php` | Manual-refresh rate limiting                                           |
| `sites.{domain}.last_update`       | `register.php`, `fetch.php` | —           | Bookkeeping only                                                       |

Dead keys from the removed per-site scheduler (`league_live_games`,
`has_live_league_game`, `has_live_game`, `has_game_today`, `games_today_date`) have been
pruned. They will not come back — nothing writes them any more.

**The public output.** One file per site, served statically.

```json
  "live": [
    /* fixtures, see below */
  ],
  "fixtures": [
    /* fixtures, see below */
  ],

    /* fixtures, see below */
  ]

```

### Fixture object

Produced by `filterFixtures()`; `isToday` is added later by `categorizeGames()`.

```json
{
  "id": 1234567,
  "date": "2026-09-12T18:30:00+02:00",
  "status": {
    "short": "NS",
    "long": "Not Started",
    "elapsed": null,
    "extra": null
  },
  "league": {
    "id": 78,
    "name": "Bundesliga",
    "logo": "https://media.api-sports.io/football/leagues/78.png",
    "round": "4. Spieltag"
  },
  "teams": {
    "home": {
      "id": 157,
      "name": "Bayern München",
      "logo": "https://…/157.png",
      "winner": null
    },
    "away": {
      "id": 165,
      "name": "Borussia Dortmund",
      "logo": "https://…/165.png",
      "winner": null
    }
  },
  "goals": { "home": 2, "away": 1 },
  "score": {
    "halftime": { "home": 1, "away": 0 },
    "fulltime": { "home": 2, "away": 1 },
    "extratime": null,
    "penalty": null
  },
  "isToday": true
}
```

Notes for consumers:

- `meta.schema` is the contract version. The plugin warns on `meta.schema` values it does
  not understand instead of rendering blanks, so bump it when a field name or shape changes.
- `league.round` is **already translated** (`4. Spieltag`, `Achtelfinale`, …).
- `teams.*.name` is **already corrected** (short German forms).
- `goals.*` is `null` before kickoff.
- `score.*.suffix` is **not** part of this payload — the plugin derives extra-time/penalty
  suffixes from `score.extratime` and `score.penalty`.
- A game finished **today** appears in **both** `live` and `results` (see the note under
  [Fixture status codes](#fixture-status-codes)).

### `api/data/standings.json`

The shared Bundesliga table. Not per-site — every widget reads the same file.

```json
{
  "meta": {
    "schema": 1,
    "generated_at": "2026-09-15T09:03:12+02:00",
    "season": 2026,
    "competition_id": 78,
    "competition_name": "Bundesliga"
  },
  "standings": [
    {
      "team": {
        "id": 157,
        "name": "Bayern München",
        "logo": "https://…/157.png"
      },
      "points": 86,
      "goalsDiff": 82,
      "group": "Bundesliga ",
      "all": {
        "played": 33,
        "win": 27,
        "draw": 5,
        "lose": 1,
        "goals": { "for": 117, "against": 35 }
      },
      "home": {
        "played": 16,
        "win": 13,
        "draw": 2,
        "lose": 1,
        "goals": { "for": 63, "against": 18 }
      },
      "away": {
        "played": 17,
        "win": 14,
        "draw": 3,
        "lose": 0,
        "goals": { "for": 54, "against": 17 }
      },
      "rank": 1,
      "form": "WDWWW",
      "status": "same",
      "update": "2026-05-11T00:00:00+00:00",
      "description": "Champions League"
    }
  ]
}
```

Which layer provides what:

| Field                                                | Source                                            |
| ---------------------------------------------------- | ------------------------------------------------- |
| `points`, `goalsDiff`, `all`, `home`, `away`, `rank` | **Calculated locally** from all league fixtures   |
| `form`, `status`, `update`                           | Merged from the cached API standings (per team)   |
| `description`                                        | Merged from the cached API standings **by rank**  |
| `group`                                              | Set to `"Bundesliga"` when the team is first seen |

Sort order: points ↓, goal difference ↓, goals for ↓. `rank` is then assigned by position.

## Configuration

`backend/config/api-config.php` returns an array. The two credentials (`api_key` and
`shared_secret`) are read from the gitignored `backend/config/secrets.php` — see
[operations.md](operations.md#security).

| Key                           | Value                               | Purpose                                             |
| ----------------------------- | ----------------------------------- | --------------------------------------------------- |
| `api_key`                     | _secret_                            | api-sports.io key, sent as `x-apisports-key`        |
| `league_ids.bundesliga`       | `78`                                | Competition used for standings                      |
| `default_season`              | `getCurrentSeason()`                | July–June; see `utils.php`                          |
| `limit_last`                  | `15`                                | Finished games requested per team                   |
| `limit_next`                  | `15`                                | Upcoming games requested per team                   |
| `default_widgets`             | `["matches","standings","results"]` | Written into new mapping entries                    |
| `shared_secret`               | _secret_                            | `register.php` auth                                 |
| `data_path`                   | env-dependent, trailing slash       | Where `*.json` is written                           |
| `intervals.api_cache_refresh` | `60`                                | Minutes between `getStandings()` calls              |
| `intervals.http_rate_limit`   | `5`                                 | Minutes between manual `fetch.php` calls per domain |

Only those two `intervals` are live. The scheduling intervals
(`live_game`, `no_live_game`, `standings_live`, `standings_no_live`) were removed along with
the per-site scheduler — see [D2](architecture.md#d2--the-cron-always-updates-everything).

## Fixture status codes

api-sports.io short codes, and how each subsystem treats them.

| Code   | Meaning               | `categorizeGames` | `calculateStandings` counts it? |
| ------ | --------------------- | ----------------- | ------------------------------- |
| `TBD`  | Time to be defined    | not started       | no                              |
| `NS`   | Not started           | not started       | no                              |
| `1H`   | First half            | in play           | **yes**                         |
| `HT`   | Half time             | in play           | **yes**                         |
| `2H`   | Second half           | in play           | **yes**                         |
| `ET`   | Extra time            | in play           | **yes**                         |
| `BT`   | Break (during ET)     | in play           | **yes**                         |
| `P`    | Penalties in progress | in play           | **yes**                         |
| `LIVE` | Live                  | in play           | no                              |
| `INT`  | Interrupted           | in play           | no                              |
| `SUSP` | Suspended             | in play           | no                              |
| `FT`   | Full time             | finished          | **yes**                         |
| `AET`  | After extra time      | finished          | **yes**                         |
| `PEN`  | After penalties       | finished          | **yes**                         |
| `AWD`  | Awarded               | finished          | **yes**                         |
| `WO`   | Walkover              | finished          | **yes**                         |

> The two columns disagree for `LIVE`, `INT` and `SUSP`: such a game is shown in the
> `live` bucket but its score is **not** added to the table. That is intentional — those
> codes mean the match is not in a countable state — but it means a visible live score can
> briefly disagree with the table. Worth confirming against real behaviour before changing.
>
> A game that is `isToday` **and** finished lands in **both** `live` (the "half-life" rule,
> so it stays visible in the Spielplan tab until midnight) **and** `results` (so the
> Ergebnisse tab and the form widget show it straight away).

## Round translations

`translateRound($round, $league_id)`.

**Bundesliga (`league_id === 78`, strict):**

| Input                 | Output         |
| --------------------- | -------------- |
| `Regular Season - 12` | `12. Spieltag` |
| `Relegation Round`    | `Relegation`   |

**Exact matches:**

| Input                                    | Output                |
| ---------------------------------------- | --------------------- |
| `1st Round` / `2nd Round`                | `Runde 1` / `Runde 2` |
| `Round of 16` / `8th Finals`             | `Achtelfinale`        |
| `Quarter-finals`                         | `Viertelfinale`       |
| `Semi-finals`                            | `Halbfinale`          |
| `Final`                                  | `Finale`              |
| `1st`–`3rd Qualifying Round`             | `Qualifikation`       |
| `Play-offs` / `Knockout Round Play-offs` | `Playoffs`            |
| `Club Friendlies` … `Club Friendlies 5`  | `Freundschaftsspiel`  |
| `Relegation Round`                       | `Relegation`          |

**Pattern matches:** `League Stage - N` → `Ligaphase`, `Group Stage - N` → `Gruppenphase`,
anything containing `Club Friendlies` → `Freundschaftsspiel`.

**Fallback:** the original string is returned unchanged.

## Team name corrections

`getTeamNameCorrections()` — keyed by **team ID**, applied by `correctTeamName()`.

| Team ID | Corrected name         | Upstream value             |
| ------- | ---------------------- | -------------------------- |
| `192`   | `1. FC Köln`           | `1.FC Köln`                |
| `163`   | `Bor. Mönchengladbach` | `Borussia Mönchengladbach` |
| `164`   | `1. FSV Mainz 05`      | `FSV Mainz 05`             |
| `182`   | `1. FC Union Berlin`   | `Union Berlin`             |
| `168`   | `Bayer 04 Leverkusen`  | `Bayer Leverkusen`         |

> **Always verify the ID before adding an entry.** A previous revision mapped
> `180 => 'TSG Hoffenheim'`, but `180` is **1. FC Heidenheim** — Hoffenheim is `167`. The
> wrong ID mislabelled a full row of the table, in every widget, and was only noticed by eye.
